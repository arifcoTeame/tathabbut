### الوصول وحقوق استخدام البيانات

تعرض [صفحة API الرسمية](https://dorar.net/article/389) خدمة لإظهار نتائج بحث الموسوعة في المواقع. وتذكر [الأسئلة الشائعة](https://dorar.net/feedback) أن الموسوعات مخصصة للبحث والتصفح، وأن نسخها وتنزيلها للاستخدام المحلي غير مسموح. إتاحة البحث عبر API لا تُثبت بذاتها حق إعادة توزيع قاعدة محلية. لذلك لم تُنسخ مجموعة إضافية، ولم تُسجّل بيانات مصدر ناجحة وهمية لتجاوز هذا العائق. يلزم تحديد استخدام مسموح به أو الحصول على حزمة مناسبة الحقوق قبل تشغيل الجمع.

## أدوات المراجعة والاستيراد

جميع الأوامر التالية من مجلد `backend/`. الأداة لا تضم نتائج البحث إلى القاعدة تلقائياً.

### 1. التقاط نتائج بحث مختارة بعد تأكيد الاستخدام المسموح

```bash
python scripts/fetch_hadith.py --confirm-permitted-use --limit 5
```

- تستخدم `https://dorar.net/dorar_api.json?skey=...` فقط؛ لا تتبع التحويلات إلى مسارات بديلة.
- تحفظ كل استجابة ناجحة في `data/review/hadith_dorar/hadith-candidate-NNN.json` مع العبارة، ورابط الطلب، ووقت الاسترجاع بتوقيته، والاستجابة الأصلية، وبصمة SHA-256.
- تسجل المحاولات في `data/review/hadith_dorar/status.json`، وتتوقف عند الرفض أو تحديد المعدل أو خطأ آخر. لا تعيد المحاولة تلقائياً.
- تستأنف من الاستجابات المحفوظة بعد فحص بصماتها؛ الافتراضي خمسة طلبات جديدة بفاصل ثانيتين. يمكن تحديد دفعة أصغر.
- `--confirm-permitted-use` إقرار من المشغّل، وليس إذناً يمنحه الموقع. لم تُشغّل دفعة الجمع لعدم توفر إذن مناسب ووجود رفض الوصول.

### 2. اختيار النتيجة المطابقة يدوياً

يُعدّ المراجع ملف `selection.json` خارج ملف العيّنة. هذا قالب بنيوي؛ القيم بين الأقواس يجب أن تُنقل من مصدر متاح، وليست بيانات جاهزة:

```json
{
  "records": [{
    "id": "chosen-record-id",
    "text": "<اقتباس حرفي متصل من النتيجة>",
    "narrator": "<الراوي كما في المصدر>",
    "grades": [{
      "muhaddith": "<المحدّث>",
      "source": "<الكتاب>",
      "ref": "<الصفحة أو الرقم>",
      "grade": "<خلاصة الحكم حرفياً>",
      "class": "<الفئة المطابقة للحكم>"
    }],
    "evidence": [{
      "grade_index": 0,
      "snapshot": "hadith-candidate-013.json",
      "result_html": "<مقطع نتيجة واحدة كاملاً كما ورد داخل الاستجابة>",
      "reviewed_at": "<تاريخ الاختيار بصيغة YYYY-MM-DD>",
      "review_note": "<سبب اختيار الرواية وملاحظة نطاق المطابقة>"
    }]
  }]
}
```

لكل درجة دليل مستقل يربطها بنتيجة واحدة. يجب أن يكون الاقتباس متصلاً في متن المصدر بعد إزالة التشكيل والترقيم فقط؛ لا تُقبل الكلمات المستبدلة أو إسناد حكم رواية إلى لفظ آخر لمجرد التقارب. لم تُغيّر ملاحظات «بلفظ مقارب» في السجلات القديمة؛ تحتاج إعادة مراجعتها إلى المصدر عند توفره.

الفئات المسموحة ذات الأحكام الصريحة هي `authentic` و`weak` و`very_weak` و`fabricated` و`baseless`. تُرفض العبارات المركّبة أو غير المعروفة بدلاً من تخمين فئتها. نطاق هذا الفحص مطابقة النص والإحالة، وليس استقصاء جميع أحكام المحدّثين أو ترجيحها.

### 3. فحص الدليل وتصدير ملف مستقل

عند التشغيل من `backend/` تقع مجلدات البيانات في `../data`:

```bash
python scripts/validate_hadith.py --selection ../data/review/hadith_dorar/selection.json --export ../data/review/hadith_dorar/reviewed.json
```

يرفض المدقق أي نتيجة غير موجودة حرفياً في الاستجابة المحفوظة، وأي اختلاف في النص أو الراوي أو المحدّث أو الكتاب أو الرقم أو الدرجة، وأي فئة حكم لا تطابق العبارة المسجلة. يشترط معرّفات فريدة ودليلاً لكل درجة. يضيف الناتج وقت الاسترجاع والرابط والبصمة والنص الأصلي والحقول المرجعية إلى الدليل. يرفض التصدير فوق ملف العيّنة؛ الدمج خطوة منفصلة بعد مراجعة النتيجة وحقوق الاستخدام.

**حدود الأداة:** تعذّر اختبار محلل نتائج API على استجابة حية بسبب `403`. اجتاز اختبارات محلية ببيانات صناعية موسومة، ويتوقف إذا اختلف تنسيق الخدمة عن التنسيق المدعوم. بصمة الاستجابة تكشف تغيير النسخة المحفوظة، ولا تُعد توقيعاً رقمياً من المصدر.

### 4. فحص القاعدة والاختبارات المحلية

```bash
python scripts/validate_hadith.py
python -m pytest tests/test_hadith_review.py -q
```

أضيفت 26 حالة اختبار، منها وقف الجلب عند `403/429` دون إعادة محاولة، ورفض السجل بلا دليل، وكشف تغيير الاستجابة، ورفض اختلاف النص والدرجة والإحالة، وحماية معرّفات السجلات القديمة وملاحظات رواياتها. فحص السجلات القديمة هنا بنيوي فقط؛ أي سجل جديد يحتاج دليلاً محفوظاً يجتاز فحص المصدر قبل دمجه.

## المراجعة الثانية — 3 أكتوبر 2026 (60 حديثاً إضافياً، الإصدار 0.6.0)

**الهدف:** تنوع الحالات لا كثرة العدد: صحيح، حسن، ضعيف، ضعيف جداً، موضوع، لا أصل له، نفي عام («لا يصح»)، حديث اختلف فيه المحدّثون، ومقاطع من أحاديث طويلة.

**الطريقة:**
1. الاستعلام عبر الواجهة البرمجية الموثقة للدرر `https://dorar.net/dorar_api.json?skey=…` بعد عودتها إلى العمل، بنسخ مُعان لاستجابة الواجهة (لم يكن الالتقاط البايتي بـ`fetch_hadith.py` متاحاً من بيئة المراجعة). لذلك يحمل كل سجل جديد `provenance.method = assisted_api_transcript` مع الاستعلام وتاريخ الاسترجاع والمراجعة.
2. اختيار الموضع: البخاري أو مسلم إن وُجد، وإلا الألباني، وإلا محدّث آخر بحكم صريح. حتى موضعين لكل حديث.
3. فحص آلي (`validate_hadith.py`) يتحقق أن نص السجل اقتباس متصل من `dorar_text` بعد إزالة التشكيل، وأن كل حكم مُدرج في جدول الأصناف؛ يفشل الفحص عند أي حكم غير مُدرج.
4. الحكم يُنقل حرفياً، ويُوسم المصدر الثاني «بلفظ مقارب» إذا اختلف لفظه عن نص السجل.

**ما لم يُضف:** «تفاءلوا بالخير تجدوه» لم يُعثر عليه بأي صيغة؛ و«سافروا تصحوا» أُسقط لأن الدرر تعرض حكم الألباني «ضعيف» مع إشارة إلى تصحيحه لاحقاً ولم نطابق الموضع الثاني.
